# 공고 자격조건 추출 (LLM)

공고 원문에서 신청 자격 조건을 뽑아 스키마 v0.6 JSON으로 정리하는 단계입니다. 담당: 정예은

- 대상: 서울·전국 공고 73건 (원문 텍스트·RAG 검색은 305건 전부, 타 지역 공고는 추출·판정하지 않음)
- 이 브랜치에는 프롬프트 v1, 추출 정답셋 30건, v1 개발용 15건 추출 결과(Terra)가 있습니다

## 폴더

| 경로 | 내용 |
| --- | --- |
| `prompts/extract_v1.md` | 추출 프롬프트 v1. 모델에는 `## [프롬프트 본문]` ~ `## [실행 지시]` 사이만 보냄 (머리말의 변경 이력은 보내지 않음) |
| `prompts/target_ids_gold30_v4.txt` | 정답셋 30건 공고ID |
| `prompts/target_ids_gold30_v4_dev.txt` / `_eval.txt` | 개발용 15 / 평가용 15. 프롬프트는 개발용만 보고 고치고, 평가용은 최종 점수에만 씀 |
| `gold/extract_gold30/` | 추출 정답셋 30건 (Claude 초안 → 사람 검토·수정). 설명은 `gold/README.md` |
| `results/extract_v1_dev_terra/` | 프롬프트 v1 + `gpt-6.1-terra`로 개발용 15건을 추출한 결과 |

## 결과 폴더 파일

- `PBLN_*.json`: 공고별 추출 결과, `conditions_v1_dev_terra.json`: 15건 합본
- `evidence_check.csv`: 근거 문장이 원문에 그대로 있는지 검사 (`근거_검증` false = 원문에 없는 문장)
- `schema_check.csv`: 허용값 밖 값, 빠진 칸 검사
- `compare_gold.csv`: 정답셋과 공고별 비교 (정밀도·재현율), `compare_gold_diff.txt`: 공고별로 빠진 것·더 뽑은 것
- `run_info.json`, `run_log.csv`: 모델·설정, 공고별 토큰·비용

## v1 개발용 15건 결과 (11/09)

같은 프롬프트로 세 모델을 비교해 Terra를 골랐습니다.

| | Luna | **Terra** | Sol |
| --- | --- | --- | --- |
| 중요한 조건 정확도 (F1, 나이·지역·업력·사업자등록 등 7칸) | 0.87 | **0.94** | 0.92 |
| 중요한 조건 빠뜨린 개수 (정답 82개 중) | 11 | **4** | 5 |
| 구조 일치 (트랙 수·대안조건 유무) | 10/15 | **13/15** | 12/15 |
| 근거 문장이 원문에 없는 비율 | 16% | **1.3%** | 1% |
| 뽑은 것 중 맞는 비율 (낮을수록 쓸데없이 많이 뽑음) | 0.62 | 0.55 | 0.47 |
| 15건 비용 | 약 146원 | 약 740원 | 약 2,300원 |

- 남은 문제: 자격이 아닌 내용(산정 방법, 정산 규칙, 서류 형식, 신청 횟수 제한)을 `기타조건`·`제외대상`으로 더 뽑음 → 프롬프트 v2에서 고칠 예정
- 결과를 만든 실행·비교 스크립트(`run_extraction.py`, `compare_gold.py`, `verify_extraction.py`)는 아직 이 브랜치에 없습니다

## 주의

- 판정 정답셋(함정상세 포함 CSV)은 이 브랜치에 없습니다. 추출할 때 모델에 넣지 않습니다
- `gold/README.md`의 경로(`prompts/...`, `output/texts/...`)는 원래 작업 폴더 기준입니다
