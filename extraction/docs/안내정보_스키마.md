# 안내정보 스키마 v0.3 (2026-11-17: 금리·자부담 뺌 / v0.2 11-17, v0.1 11-16)

자격 조건 스키마(v0.6 + 업종명)와 짝을 이루는 두 번째 스키마. **신청 가능 여부와 상관없이 화면에 보여줄 정보**를 담는다.

- 자격 조건 스키마: 판정용 (나이·지역·업력·업종 …) → `extraction/service_v4/`
- 안내정보 스키마: 표시용 (지원금·서류·우대·일정 …) → 이 문서

## 0. 원칙

1. **API에 칸이 있으면 API 값을 쓴다.** LLM으로 다시 뽑지 않는다 (기관, 접수기간, 신청방법, 링크, 문의처, 첨부파일)
2. **API에 없는 것만 원문 본문에서 추출한다.** 추출한 값에는 반드시 `근거`(원문 문장 그대로)를 붙인다
3. 원문에 없으면 `null` (중복지원은 `미확인`). 추측하지 않는다
4. 금액·날짜·비율은 원문 숫자만. 계산하거나 추정하지 않는다
5. 사업 전체 예산(지원규모)은 1인당 지원금에 넣지 않는다
6. 예외 문구는 규칙으로 바꾸지 않고 원문 그대로 둔다
7. 자격 조건(누가 신청할 수 있나)은 넣지 않는다. 자격 스키마에 있다

대상: **서비스 62건만** (서울 14 / 전국 48, `prompts/target_ids_seoul_national_62.txt`). API 칸도 원문 추출도 62건만 (11/16 결정).

| --- | --- | --- | --- |

| 지원내용 | supportDetail | 거의 전부 | 지원 항목 하나에 한 줄, 최대 5개. `항목`: 짧은 이름 (예: "리모델링"). `내용`: 한 줄로 줄여 써도 되지만 금액·기간·횟수는 원문 숫자 그대로. 숫자는 근거 문장에 있어야 함 (코드로 확인). 전체 소개 글은 API `summary`가 따로 있음 |
| 제출서류 | submissionDocs | 제출서류 항목이 있을 때 (약 49건) | 서류 하나에 한 줄. `필수`: **"이 서류가 없으면 신청이 안 되나?"** 안 되면 true ("마이데이터 비동의 시", "법인만"도 true), 신청은 되고 혜택만 못 받으면 false ("선택", 가점·우대·자부담 면제 증빙, "희망 시"), 이때 `대상`에 이유를 적음 (예: "자부담 면제받으려면" → 화면 "선택 · 자부담 면제받으려면") (11/17 결정, 후처리 코드가 맞춤). `대상`: "법인만"처럼 누가 내는지 원문에 있으면 적음, 없으면 null. "택1"이면 한 줄로 "A 또는 B", true |
| 우대사항 | bonusPoints | 우대·가점 항목이 있을 때 (약 21~37건) | 우대 항목 하나에 한 줄. `가점`: 점수가 숫자로 있으면 숫자, 없으면 null ("우대" 표시만 있는 경우) |
| 모집일정 | rounds | 세부사업·차수마다 날짜가 다를 때, 또는 API와 원문 날짜가 다를 때 (3절, 최소 4건) | API 날짜 하나로 충분하면 비움. `차수`: "1차"나 세부사업명 같은 원문 이름 ("일반형 1차"). 날짜는 YYYY-MM-DD. 일(日)까지 없으면 날짜는 null, `원문`에 "5월" (v0.2 추가) |

- 건수는 62건 원문에서 단어로 검색한 대략의 숫자 (실제 추출 후 다시 셈)
- 원문에 없으면 `null` (중복지원은 `미확인`). 추측해서 채우지 않음

### 자격 스키마와 겹치는 부분
같은 원문 문장이 두 스키마에 다 들어갈 수 있다. **쓰는 곳이 달라서** 둘 다 둔다.

| 내용 | 자격 스키마 (판정·체크리스트) | 안내정보 스키마 (상세 화면) |
| --- | --- | --- |
| 자부담 | 체크리스트에 "자부담 20% 필요" 한 줄 (`기타조건`, 구분 자부담) | 없음 (v0.3에서 뺌) |
| 중복지원 | 신청을 막는 경우만. 예: "이 사업을 이미 받은 기업은 신청 불가" → 해당되면 신청 못 함 (`제외대상`, 유형 중복수혜) | 같이 받을 수 있는지 안내. 예: "다른 정부 지원사업과 중복 가능" / "불가" / 문구 없으면 "미확인" |
| 우대사항 | 없음 (우대는 못 맞춰도 신청할 수 있어서 자격이 아님) | 가점·우대 항목 목록. 예: "여성기업 가점 2점" |

- 같은 문장을 두 스키마에 다 넣을 때는 근거도 같은 문장을 쓴다
- 우대사항을 판정 체크리스트에도 보여줄지는 판정 담당(나주희님)이 정한다

## 3. API와 원문이 다를 때

### 접수기간
서비스 62건 중 37건은 API 접수기간 값이 날짜가 아니다 (11/16 확인).

| API 접수기간 값 | 건수 | 뜻 | 처리 |
| --- | --- | --- | --- |
| 날짜 (`2026-10-01 ~ 2026-10-26`) | 25 | 정상 | API 날짜 사용 |
| 예산 소진시까지 | 22 | 돈이 떨어질 때까지 계속 받음 | 상시 모집 (rolling) |
| 상시 접수 | 8 | 언제든 신청 가능 | 상시 모집 |
| 선착순 마감 / 선착순 접수 / 모집 마감시 | 3 | 정원이 차면 끝 | 상시 모집 |
| **세부사업별 상이 / 접수방법별 상이** | **4** | 세부사업마다 날짜가 다름 | **원문에서 날짜 추출 → `모집일정`** |

**원문에서 날짜를 뽑는 4건**: 날짜가 없는 게 아니라, 세부사업마다 날짜가 달라서 API에 한 줄로 적지 못한 경우
- 117676 희망리턴패키지 원스톱폐업지원
- 119739 소상공인 온라인판로 지원
- 124232 투·융자 연계 기술개발사업
- 126928 오픈이노베이션 지원

**연장 공고**: API와 원문의 마감일이 다를 수 있다
- 예: API "마감 10월 26일", 원문 "접수기간을 11월 9일까지 연장합니다"
- 원문 날짜를 쓴다 (원문이 최신이라고 본다)

**화면에 보여줄 날짜**

| 경우 | 화면 날짜 |
| --- | --- |
| 원문에 날짜가 없음 | API 날짜 |
| API가 날짜가 아님 ("세부사업별 상이") | 원문 날짜 |
| 둘이 다름 (연장 등) | **원문 날짜** |

→ 백엔드: 원문 날짜와 API 날짜가 다르면 원문 날짜를 쓴다

### 제출서류
- API에는 서류 목록 칸이 없다. 신청방법 칸(`reqstMthPapersCn`)에는 "이메일 접수, 제출서류는 스캔본으로"처럼 방법만 있다 (62건 중 서류 이름이 나오는 건 "신청서 제출" 2건뿐)
- 서류 목록은 원문 본문에서 추출한다 (49/62건에 "제출서류" 있음)

## 4. 확인 방법
- 근거 문장이 원문에 있는지 코드로 확인 (`verify_extraction.py`와 같은 방식)
- 정답셋은 만들지 않는다 (11/16 결정, 표시용이라 판정에 영향 없음). 대신 숫자 칸(최대지원금·가점·날짜)이 근거 문장에 그대로 있는지 코드로 확인하고, 결과를 사람이 한 번 훑어본다
