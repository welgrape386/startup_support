기준 스키마: v0.6 (11/04, 사용자 범위 서울 + 기준일에 날짜 허용)

- **칸 정의와 값 규칙의 원본은 `스키마.md`** 다. 이 문서는 "헷갈릴 때 어떻게 판단하나"와 실제 공고 예시만 담는다 (같은 규칙을 두 곳에 적지 않는다).
- LLM 프롬프트는 두 문서를 참고해 `prompts/extract_vN.md`로 따로 만든다.

## 1. 무엇을 뽑고, 무엇을 뽑지 않나

### 1-1. 뽑는 것: 신청 자격 조건

- 못 맞추면 **신청 자체가 불가능한** 조건
- 예: "사업자등록증 소재지 경기지역", "소상공인확인서 보유 업체", "국세·지방세 체납 중인 경우 신청 제한"

### 1-2. 뽑지 않는 것

| 종류 | 예 | 이유 |
| --- | --- | --- |
| 지원내용 | "쇼호스트 지원, 최대 1시간 방송" | 신청 가능 여부와 무관 (11/4 안내정보 스키마에서) |
| 일정 | "10.2.~10.16. 신청" | API 칸에 있음 |
| 제출서류 목록 | "참가신청서, 상품기술서 제출" | 자격 아님 (아래 1-4 예외) |
| 평가·선정 방식 | "평균 70점 이상 고득점순 선정" | 신청한 사람 중 누굴 뽑을지의 문제 |
| 선정 후 취소 사유 | "과제선정 확정 이후라도 자부담금 확보 약속 불이행 시 취소 가능" | 선정 뒤 지킬 의무 |
| 동어반복 조항 | "지원대상 자격요건에 해당하지 않는 기업" | 새로운 정보가 없음 |

### 1-3. 자격 vs 우대 구분

- "~인 자", "~에 한함", "~는 신청 불가" → **자격** (뽑음)
- "~시 가점", "~우대" → **자격 아님** (뽑지 않음)
- 우대를 자격으로 잘못 뽑으면 신청 가능한 사람에게 🔴가 나간다

### 1-4. 제출서류 섹션 규칙

- 서류 목록만 보고 자격을 **추론하지 않는다**
    - 예: "최근 2개년 재무제표" → 업력 2년 이상으로 해석 금지
- 단, "~만 인정"처럼 **명시적 제한**은 자격으로 가져온다
    - 예: "유효기간이 2026.4.1.~2027.3.31.인 소상공인확인서만 인정" → `보유요건.유효기간_조건`

### 1-5. 같은 조건이 여러 곳에 나오면

신청자격·평가 제외·유의사항 등에 반복되면 **'신청자격/신청대상' 섹션의 문장**을 근거로 쓴다.
한 조건이 원문 두 곳 이상에 나뉘어 있으면 값을 가장 직접적으로 보여주는 문장 하나를 쓴다 (스키마 1-2).

### 1-6. 서울 사용자와 타 지역 공고

- 사용자는 서울의 예비창업자·초기창업자지만, **타 지역 공고도 똑같이 추출한다** (스키마 0절: 검색에서 빼지 않고 판정에서 처리)
- 지역 칸을 서울 기준으로 줄이거나 건너뛰지 않는다. 원문 지역·유형·사후충족을 그대로 적어야 판정 코드가 예비창업자(🟡/⚪/🔴)와 기창업자(🔴, "사업장 이전 조건 공고")를 나눌 수 있다 (스키마 6-3)

### 1-7. 근거 검증에 실패하면

- 코드가 근거를 원문에서 못 찾으면(`근거_검증: false`) 그 칸만 1회 다시 추출한다
- 다시 해도 못 찾으면 그 칸을 `상태: 불명확`으로 바꾼다 → 판정 ⚪ (스키마 1-2)

## 2. 칸별로 헷갈리는 경우

값을 어떻게 적는지(예: "39세 이하" → `max: 39, 경계_max: 이하`)는 스키마 3절에 있다. 여기에는 **원문을 읽고 판단할 때 자주 틀리는 것**만 적는다.

| 칸 | 헷갈리는 경우 | 이렇게 한다 | 스키마 |
| --- | --- | --- | --- |
| 나이 | 나이가 나와도 신청자 나이가 아닐 수 있다 | "만 39세 이하 **대표자**" → `대상: 대표자` (신청자 나이와 비교). "만 60세 이상 **근로자를 채용한** 기업" → `대상: 채용대상` (신청자와 비교 안 함), 채용 조건은 `기타조건`(`구분: 채용`)에도 남김. 5-3 함정 예시 참고 | 3-2, 3-11 |
| 나이 | "보험나이 20세 ~ 65세"처럼 보험나이로 적혀 있다 | `나이_기준: 보험나이`, 숫자는 원문 그대로. 만 나이로 바꾸지 않는다 (계산은 판정 코드) | 3-2 |
| 나이 | "40세 미만"을 39세 이하로 바꾸고 싶어진다 | 원문 그대로 `max: 40, 경계_max: 미만`. 변환은 판정 코드가 한다 | 3-2 |
| 기준일 (나이·지역·업력·사업자등록·창업이력·제외대상) | "2026. 10. 2. 기준 39세 이하"처럼 공고일이 아닌 특정 날짜가 기준이다 | 그 날짜를 그대로 `기준일: "2026-10-02"`. `명시없음`으로 적으면 판정하는 날 기준으로 계산돼, 그 사이 나이 경계를 넘은 사람이 틀린 🔴를 받는다. "공고일(2026.10.14.) 기준"처럼 공고일에 날짜를 붙인 경우는 `공고일`. 출생일·개업일 날짜가 함께 있으면 `출생일_범위`·`창업일_범위`도 채운다 | 1-3 |
| 지역 | "기업 소재"와 "거주"가 한 문장에 섞여 있다 | 소재지와 거주지는 다른 `유형`이다. 하나로 합치지 않는다 | 3-4 |
| 지역 | "광주", "전남"처럼 옛 명칭이 나온다 | 시도는 `전남광주통합특별시`, 옛 구역은 `권역`에 남긴다 | 3-4 |
| 지역 | "본사 또는 공장", "거주지와 사업장 모두 ○○시" | `유형`에 둘 다 넣고, "또는"이면 `유형_결합: 하나만`, "모두"·"~및 ~이 ○○시"면 `유형_결합: 모두`. 이건 `대안조건`이 아니다 | 3-4 |
| 지역 | "○○에서 창업 예정인 자", "사업장 (예정)소재지"처럼 창업할 곳을 정한다 | 소재지 유형(`사업장소재지`)으로 적는다. 판정 코드가 예비창업자는 `창업예정지`, 초기창업자는 `사업장소재지`와 비교한다. 거주인지 창업 장소인지 원문으로 알 수 없을 때만 `명시없음` | 3-4, 4절 |
| 지역 | "선정 후 ○개월 이내 ○○로 이전", "협약 전까지 ○○에 사업자등록" | `사후충족_허용: true`와 기한을 빠뜨리지 않는다. 기창업자 판정에는 안 쓰지만 예비창업자 🟡 판정에 쓴다 | 3-4, 6-3 |
| 업력 | "2025. 1. 1. 이후 창업", "2024. 7. 1. 이전 개업"처럼 날짜로 적혀 있다 | `창업일_범위`에 날짜 그대로. 개월로 바꾸지 않는다. "이후 **폐업**"은 업력이 아님 (`창업이력`·`제외대상`) | 3-5 |
| 업력 | "개인: 개업일 기준 / 법인: 법인설립등기일 기준"처럼 개인·법인 기준이 다르다 | **기간이 같으면** `업력` 칸 하나에 기간, `업력_기준: 명시없음`, 기준 차이는 `기타조건`(`구분: 기타`, `판정가능: true`)에 남긴다 (프로필 `창업일`이 이미 개인 = 사업자등록일, 법인 = 법인설립등기일). **기간이 다르면** 개인사업자·법인 `트랙`으로 나눈다 | 3-5 |
| 업력·기간 | "90일 이상", "1년 6개월 이내"처럼 일·혼합 단위다 | 개월로 바꾼다. 30일 = 1개월, 나머지는 올림 (90일 = 3, 100일 = 4), 1년 6개월 = 18 | 1-3 |
| 업력 | "초기창업기업"처럼 단계명만 있다 | 원문에 단계명이 있을 때만 `단계`를 채운다. 숫자를 보고 단계를 짐작해서 채우지 않는다 | 3-5 |
| 신청자_유형 | "○○대 재학생", "대학(원)생 창업팀"처럼 학생이 신청 대상이다 | `신청자_유형: ["대학생"]`에만 적는다 (대학원생 포함). `특수자격`의 `대학생`에 중복으로 넣지 않는다 | 3-1 |
| 사업자등록 | "예비창업자 및 창업 3년 이내 기업"처럼 예비창업자와 기창업자를 같이 받는다 | `업력` 칸에 넣지 말고 **항상 `트랙`** 으로 나눈다 (`예비창업` / `기창업`). 최상위에 넣으면 예비창업자가 🟡로 잘못 판정된다 | 3-6, 3-13 |
| 사업자등록 | "소상공인", "중소기업" 대상인데 사업자등록 언급이 없다 | 기업이 대상이면 `필수`. 신청자_유형은 `["개인사업자", "법인"]`, 규모 표현은 `기업규모.구분`에만 | 3-1, 3-6, 3-8 |
| 업종 | 공고 끝에 KSIC 제외업종 표가 몇 쪽씩 붙어 있다 | 표 전체를 옮기지 않는다. 출처("소상공인 정책자금 융자제외 업종")가 있으면 `제외_참조`만 | 3-7 |
| 제외대상 | 제외 문장에 기준일과 "단, ~은 제외"가 붙어 있다 | `기준일`과 `예외`를 빠뜨리지 않고 같이 적는다 (예: "단, 창업 3년차 미만은 제외") | 3-10 |
| 제외대상 | "프랜차이즈 가맹점", "대기업 운영 프랜차이즈 직영점"이 제외 대상에 있다 | 업종이 아니라 영업 형태라 `유형: 프랜차이즈`로 적고 `프랜차이즈.범위`·`대기업_한정`을 채운다. "프랜차이즈 **제품**"은 `취급불가품목` | 3-10 |
| 제외대상 | 어느 유형에도 안 맞는다 ("사업장이 공유오피스·자택인 자", "4대보험 연체 중인 자", "불공정거래 위반자") | `유형: 기타`, `판정가능: false`. 프로필로 맞춰볼 칸이 없어 ⚪ + 체크리스트로 처리된다. `기타조건` 칸과 헷갈리지 않는다 | 3-10 |
| 제외대상 | 업종 제한이 제외대상 목록에도 있다 | 제외대상에는 `유형: 업종제외` 한 줄만, 상세는 `업종` 칸에 (중복 금지) | 3-10 |
| 기타조건 | 어느 칸에도 딱 맞지 않는다 | 억지로 끼우지 말고 `기타조건`에. 자부담(현금 매칭)도 `구분: 자부담`으로 남긴다 | 3-11 |

## 3. 대안조건·트랙 적는 법

규칙은 스키마 3-12(대안조건), 3-13(트랙). JSON 예시도 스키마 3-12에 있다.

### 3-1. 트랙별 조건이 다른 경우

최상위에는 모든 트랙 공통 조건만, 다른 부분은 `트랙`에.

```json
"트랙": [
  {"이름": "예비창업", "조건": {"사업자등록": {"상태": "있음", "값": "불가", "근거": "..."}}},
  {"이름": "기창업", "조건": {"사업자등록": {"상태": "있음", "값": "필수", "근거": "..."},
                                  "업력": {"상태": "있음", "max_개월": 36, "경계_max": "이하", "근거": "..."}}}
]
```

### 3-2. "A 또는 B" 조건일 때 최상위 칸

"만 39세 이하 또는 여성 대표자"처럼 대안조건으로 뽑은 경우(대안조건 목록은 스키마 3-12 예시), 최상위 `나이`·`성별` 칸은 이렇게 적는다.

```json
"나이": {"상태": "대안조건", "min": null, "max": null, "경계_min": null, "경계_max": null,
        "나이_기준": null, "기준일": null, "출생일_범위": null, "대상": null, "근거": null},
"성별": {"상태": "대안조건", "값": null, "대상": null, "근거": null}
```

- `없음`으로 적지 않는다. `없음`은 원문에 조건이 아예 없을 때만 쓴다.
- 조건 값과 근거는 `대안조건` 목록에만 적는다 (최상위 칸에 중복으로 적지 않는다).

## 4. 데이터 특성

### 4-1. 추출 대상 (11/04 기준)

- ①②③ 해당 342건 중 본문 추출 성공 **307건** (이미지 공고 33건·2단 편집 2건 제외)
    - 서울·전국 대상 79건 (공고명 태그 `[서울]` 14건 + 태그 없음 65건)
    - 타 지역 대상 228건 → 추출은 똑같이 한다 (1-6)
- 공고명에 지역 태그가 없다고 지역 조건이 없는 것은 아니다. 본문에 지역 조건이 있는 공고가 있다 (칸-본문 불일치)
- "수도권"·"비수도권"은 307건 중 15건 본문에 나오지만, 자격 조건으로 쓰인 것은 1건(116904 통합공고)뿐이다. 나머지는 우대·가점·금리·권역 안내라 뽑지 않는다. 116904는 따로 확인해서 처리한다

### 4-2. 본문 추출이 필요한 이유 (기업마당 API 500건 기준)

1. **API 칸이 불충분하다.** `지원대상`은 공고마다 "중소기업" 같은 값 하나뿐이고, 나이·업력·지역 칸은 없다. 지역은 공고명 앞 `[경기]` 태그로만 알 수 있다.
2. **사업개요도 부족하다.** 첫 번째 ☞ 블록이 지원대상 요약이지만, 일부는 "공고문 참조"로 끝나고 제외대상은 거의 빠져 있다.

본문 파일 형식: pdf 66% / hwpx 21% / hwp 12% (500건 기준)

- 범위 공고 314건 실제 (2026-10-16, v4): pdf 167 / hwp 98 / hwpx 37 / jpg·png 11 / docx 1 → **이미지를 뺀 모든 형식에서 텍스트 추출** (282건 성공)
- 근거는 추출 텍스트 `texts/{공고ID}.txt`에서 복사한다 (스키마 1-2)

- API `지원대상`은 "중소기업"인데 본문은 그냥 "기업" → 칸·본문 불일치 사례 (나주희님 오류 유형표 후보)
- 근거가 PDF 줄바꿈에서 잘린다("지원 대상인 \n다른 과제") → 근거 검증 시 공백·줄바꿈 정규화 필수
- 지원제한 목록 중 동어반복 조항, 선정 취소 사유 3개, 평가 기준은 뽑지 않는다 (1-2)
